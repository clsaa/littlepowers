# v0.3 alpha evaluation report

**Date:** 2026-07-17

**Release candidate:** 0.3.0-alpha.1

**Platform:** macOS, Europe/London

**Baseline revision:** `155c782b22497ff70908f9ef3118158462300010`

This report records prerelease evidence, including corrections found during evaluation. It does not claim reliability across repeated runs. The project requires at least three runs per configuration before drawing that conclusion.

## Static and local validation

- 43 Python tests passed after the final adversarial fixes.
- All eight skill packages passed the skill validator.
- The Codex plugin manifest passed strict local validation.
- The Claude plugin passed `claude plugin validate --strict` with Claude Code 2.1.207.
- Python compilation and Ruff formatting and lint checks passed.

## GPT-5.6 Sol xhigh

**Evidence level:** model routing response and repository review.

The initial scenarios exposed two ambiguous rules: how paused work relates to a later generic implementation request, and whether a fully specified compatibility or security fix must always use the full four-document route. The router and scenarios were corrected to make explicit semantic resume mandatory and to route fixed, low-ambiguity work proportionally.

After those corrections, scenarios 1 through 9 passed. This is one evaluation campaign with targeted reruns, not three independent full-matrix runs.

## GPT-5.6 Sol max

**Evidence level:** independent adversarial implementation review.

The reviewer iteratively probed stale replacement, output-size self-bricking, hard links, paused stale work, unsafe artifact reads, worker ownership, future timestamps, artifact snapshot races, terminal replacement conflicts, state-directory swaps, workspace-root component swaps, and mixed Git/path identity.

The fixes were re-read and retested. The final verdict was `PASS` with no remaining P0/P1 issue; all 43 tests passed.

## Codex Ultra

**Evidence level:** multi-agent coordination simulation.

A root coordinator and two workers exercised coordinator-only ledger ownership. The root advanced the ledger from revision 0 to revision 8, workers remained read-only, and a stale write conflicted instead of overwriting current state.

The result validates the cooperative workflow. It does not turn ledger ownership into operating-system authorization; any process with workspace write access can still invoke the state CLI.

## Claude Fable 5 and Opus 4.8

**Evidence level:** official documentation review and strict static plugin validation.

The plugin does not select a Claude model, set effort, request hidden reasoning, or override model aliases. Its prompts are outcome-focused and its Hook adds bounded state facts rather than repeated imperative process text. No parameter conflict was found.

An authenticated Fable 5 or Opus 4.8 implementation and interruption flow was not run because the local Claude Code session was not authenticated. The accurate release status is therefore “compatible by design; authenticated flow not yet recorded.”

## Release interpretation

- xhigh, max, and Ultra have useful prerelease evidence for the behaviors listed above.
- None has completed the three-run reliability threshold across the full matrix.
- Fable 5 and Opus 4.8 have static compatibility evidence only.
- Littlepowers and Superpowers should not both act as the default workflow router in one session; that is a process-instruction conflict, not a model-parameter conflict.
