One review finding was repaired before final validation: the first draft
described Ultra only as a product mode, while a current Codex native spawn
surface may expose `ultra` as a host-specific worker reasoning value. The final
protocol now treats the actual tool schema as authoritative and requires an
explicit proposal and user authorization for Ultra or maximum effort; neither
is selected automatically.

## Compatibility and performance limits

This report establishes static/package compatibility and deterministic
default-off/worker-boundary regressions. It does not claim an authenticated
delegated implementation run, reliable speedup, token saving, or quality gain
for GPT-5.6 Sol xhigh/max/Ultra, Claude Fable 5/Opus 4.8, or any Qoder model.
Provider aliases, organization policy, and the current native tool schema can
override or remove model/effort choices.

The ordinary path gains a short static router rule but performs no additional
Agent or model call and does not read the progressive-disclosure reference.
An authorized delegated run intentionally adds worker token, latency, and
integration cost. A reliable host/role claim still requires at least three
comparable representative runs with accepted output, conflicts, duplicate
work, rework, elapsed time, and token/cost recorded only when the host exposes
them.
