Date: 2026-08-01

Platform: macOS 26.5.1, Python 3.9.6, Node.js 26.5.0, Git 2.50.1,

## Result

The stable schema-4 candidate passed the available model-independent runtime,
migration, security, skill, packaging, and four-host validation boundary. This
report is the integrated local evidence for Review Lease and the optional
Project Workflow Index; it supersedes the prerelease test counts as a release
claim.

Two pushed release candidates were correctly blocked by Windows CI. The first
exposed a false-positive review-job path-replacement check; after that runtime
fault was repaired, the second reached a previously masked POSIX-shebang test
fixture that Windows could not execute. This corrective candidate keeps path
and handle race snapshots within their respective stat interfaces, binds those
views through the device and file identity, adds a local cross-interface
regression, and captures the exact host invocation through an injected fake
process on every platform. Publication remains conditional on a final read-only
expert review of this unchanged correction, a clean corrective commit, new
Linux/macOS/Windows/Claude GitHub Actions results for that exact commit, and
exact-tag smoke before the stable GitHub Release is made public. Those external
results belong in the immutable release notes rather than being predicted here.

This report does not claim an authenticated GPT-5.6 Sol, Codex Ultra, Fable 5,
Opus 4.8/5, or Claude dynamic-workflow implementation run. It establishes
deterministic protocol behavior and that Littlepowers does not select a model,
reasoning effort, dynamic workflow, or subagent count.

## Expert review and repair trace

The first three independent reviews found release blockers in architecture and
security, host/model compatibility, and open-source release readiness. The
candidate repaired them before the aggregate run:

- objective changes now require `start --replace`, and a windowed policy
  requires an explicit `next_phase|execute` boundary;
- Contract bind, Plan validation, and fresh execution require the persisted
  resolution for the exact key, original normalized path, artifact bytes, and
  embedded Contract source-digest set;
- each Contract-bind and Plan-validation boundary is consumed once in the
  successful mutation revision, while a Compact shape may supply each of those
  two declared uses once;
- prerelease schema-4 resolutions without path/consumption data remain readable
  for recovery but cannot authorize work until re-parked and re-resolved;
- the Claude runner atomically creates metadata and linearizes gate recheck,
  job claim, and process start under the state lock, so cancellation that wins
  the lock produces no host call;
- duplicate-key job JSON is rejected, and Project Index unregister prioritizes
  the stored lexical identity before a unique resolved fallback, preventing a
  replaced symlink from removing another registered member;
- review-job reads compare each complete race snapshot through the same stat
  interface, avoiding Windows path/handle representation mismatches while
  retaining path identity, mutation, link-count, mode, size, and timestamp
  checks;
- the exact-session invocation regression captures one injected process call
  directly instead of relying on a platform-specific executable fixture;
- Windows source-digest expectations use the fixture's actual bytes;
- release identity, SECURITY support, exact-tag install/rollback instructions,
  Claude dynamic-workflow authority, and performance wording now match the
  stable release boundary.

Final verdicts are intentionally not self-asserted by this report. The release
coordinator binds them to the post-report candidate snapshot and blocks
publication on any remaining Critical or Important finding.

## Protocol and host evidence

- Schema 4 retains Outcome Lock coverage/fidelity/completion gates and adds four
  exact Review Lease policies, artifact/source binding, bounded resolution
  consumption, and recoverable schema-1/2/3 migration.
- Direct work still creates no planning gate. Lean work still uses brainstorm
  then Plan without separate specification or design; implementation remains
  one continuous product scope with reversible tasks and checkpoints.
- Hooks remain ledger-only, read-only, network-free, artifact-free,
  scheduler-free, and Project-Index-free.
- The optional Claude runner uses one exact-session `claude -p --resume`, no
  shell or model/effort override, no output persistence, no retry, and one
  bounded invocation claim.
- Codex schedules only when a callable same-task one-shot surface exists;
  Qoder and OpenCode truthfully retain manual timed continuation.
- The opt-in Project Workflow Index stores at most 16 explicit same-repository
  roots in a separate locked record. It never enumerates worktrees, writes
  member ledgers, or adds ordinary Hook/routing cost.
- In a Claude dynamic workflow, the approved Littlepowers Plan remains the sole
  product-scope and acceptance authority. The host workflow is a derived
  execution adapter; protocol compatibility is not orchestration certification.

## Security regressions

Fresh tests cover same-byte path substitution at Contract bind, Plan
validation, and execution; parent-source changes while a gate is parked and
after resolution; resolution replay; Compact dual-boundary consumption;
objective-authority leakage; missing window boundaries; cancellation at the
Claude invocation linearization point; partial initial job writes; duplicate
JSON keys; equivalent path/handle stat views; Windows replacement rejection
without leaked handles; Windows newline differences; and ambiguous two-member
symlink unregister.

The state remains fail-closed under stale revisions, open gates, invalid or
legacy authorization records, Contract/Plan drift, incomplete coverage,
unapproved scope delta, unsafe files, and runner/job-store replacement.
