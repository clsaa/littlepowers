# v0.4 alpha evaluation report

**Date:** 2026-07-17

**Release candidate:** 0.4.0-alpha.1

**Candidate revision:** `b9558cebaa3d221a71c9ae10de7d33054302f840`

**Platform:** macOS arm64, Europe/London

This report records proportional local verification and authenticated Codex forward tests for the three v0.4 disciplines. It does not claim three-run reliability or authenticated Claude-model coverage.

## Rollback and test strategy

The release was built as independent commits for systematic debugging, evidence-gated verification, lightweight review, shared packaging, and a runtime compatibility fix. Each feature first ran only its own skill validators and named contract tests.

At the aggregate release boundary:

- 49 Python tests passed, including the unchanged state and Hook suite;
- Python compilation and Ruff checks passed;
- all 11 skills passed `quick_validate.py`;
- the Codex plugin validator passed;
- Claude Code 2.1.207 strict plugin validation passed.

The first Codex forward run then exposed a packaging defect that the static validator did not catch: Codex accepts at most three `interface.defaultPrompt` entries, while the candidate had five, so the runtime ignored the set. Commit `3919ef8` reduced the set to three and added a regression assertion.

After that focused manifest repair, all 17 directly affected manifest and engineering-discipline tests, targeted Ruff checks, the Codex plugin validator, and Claude strict validation passed. The untouched state and Hook tests were intentionally not rerun locally for the small manifest/test-only repair. Final publication CI remains the fresh full 50-test cross-platform gate.

## Installation evidence
