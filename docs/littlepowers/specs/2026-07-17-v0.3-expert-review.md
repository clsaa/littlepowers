# Littlepowers v0.3 specification

**Date:** 2026-07-17

**Status:** Approved for implementation

## Scope

v0.3 hardens recovery, adds prompt-boundary continuity, makes planning proportional, documents model compatibility, and prepares the repository for external contributors. It remains one shared implementation packaged natively for Codex and Claude Code.

## Functional requirements

### Routing

- Direct work is allowed when material product, architecture, security, or compatibility decisions are absent.
- A direct task expected to span multiple tool loops may create an execution ledger without planning artifacts.
- Compact shaping records one brief that covers outcome, constraints, decision rationale, acceptance checks, approach, and execution steps.
- Full shaping creates brainstorm, spec, design, and plan artifacts in that order.
- Explicit user requests for the full workflow always select full shaping unless the user later changes that request.
- The latest user request has priority. Related corrections update the active workflow; an unrelated request preserves but does not overwrite it.

### Recovery cadence

- SessionStart handles startup, resume, clear, and compaction boundaries.
- UserPromptSubmit provides a bounded reminder before every supported prompt.
- Hook output contains factual workflow data, not a second copy of static policy.
- A subagent receives a read-only ownership reminder when the host exposes SubagentStart.
- Documentation distinguishes prompt-boundary assistance from a guarantee of model compliance. Codex Queue remains the only recommended way to defer a message until the current run finishes.

### State

- State schema 2 includes `workflow_id`, `revision`, `created_at`, `updated_at`, `status`, `phase`, `objective`, `current_task`, `next_action`, artifacts, and completed checkpoints.
- One worktree has at most one active or paused workflow.
- Every mutation, artifact read, and replacement of any prior ledger supplies the workflow ID and expected revision.
- A stale ID or revision returns a conflict without modifying state.
- Replacing any prior workflow archives the prior ledger first.
- Paused workflows require an explicit resume operation; checkpoint does not resume them implicitly.
- Schema 1 state remains readable and migrates deterministically on the next successful write.

### Trust boundary

- Hook and CLI reads share the same validation path.
- A tracked state file, unsafe ownership or permissions, linked or reparse-point state surface, non-regular state file, oversized state file, or timestamp beyond allowed future skew is rejected.
- State JSON is limited to 64 KiB. Hook context is bounded and only includes recent completed items.
- Serialized state is size-checked before replacement, so a valid mutation cannot create an unreadable ledger.
- A workflow can be completed only from `phase=verify`.
- Artifact values must be normalized, repository-relative Markdown paths. Reads require the expected workflow ID and revision, are bounded to 128 KiB, and reject links, special files, untrusted ownership or permissions, and non-UTF-8 content.
- Hooks remain local, read-only, fail-open, network-free, transcript-free, and telemetry-free.

### Multi-agent behavior

- Littlepowers does not start subagents by itself.
- Codex Ultra and Claude dynamic workflows may delegate according to host behavior.
- Only the root coordinator may mutate the ledger. Workers read artifacts through the bounded state CLI reader and report results to the coordinator.
- Independent top-level workflows use separate worktrees.

### Packaging and operations

- Codex and Claude manifests use the same semantic version.
- Add a user-facing management skill for status, pause, resume, cancel, doctor, and recovery guidance.
- Phase skills cannot be selected as standalone entry points without router selection or matching active state.
- Document installation, update, rollback, uninstall, troubleshooting, security, capability boundaries, and dated model compatibility.

### Community readiness

- Add contributing, security, code-of-conduct, changelog, issue form, and pull-request guidance.
- Add a Linux/macOS/Windows test matrix for portable state and hook behavior.
- Keep repository visibility private until the owner explicitly approves publication.

## Non-goals

- Guaranteeing that every model obeys a recovery reminder.
- Parsing chat transcripts or user prompt text in hooks.
- Replacing Codex Ultra, Claude dynamic workflows, or Superpowers' full development methodology.
- Automatically committing, pushing, opening pull requests, deploying, changing visibility, or enabling telemetry.
- Supporting several active top-level workflows in one worktree.

## Acceptance criteria

- A state created after SessionStart appears in the next UserPromptSubmit context.
- Tracked, linked, oversized, path-escaping, and future-dated state is rejected by both hook and CLI paths.
- A concurrent POSIX workspace-root or state-directory pathname swap cannot redirect lock, state, or archive writes outside the pinned store.
- Stale revisions cannot overwrite a newer checkpoint.
- A paused workflow cannot be changed until it is explicitly resumed or cancelled.
- Hook text is bounded, factual, and does not instruct the model to obey ledger values or read unvalidated paths.
- Direct, tracked-direct, compact, and full routes are distinguishable in skills and evaluation scenarios.
- GPT-5.6 Sol xhigh/max and Codex Ultra receive no model override from the plugin; Ultra uses coordinator-only writes.
- Claude Fable 5 and Opus 4.8 receive no model or effort override; documentation records validation evidence separately from live model evidence.
- Unit tests, skill validation, Codex plugin validation, and Claude strict plugin validation pass.
