# Littlepowers v0.3 design

**Date:** 2026-07-17

**Status:** Approved for implementation

## Architecture

Littlepowers remains a thin protocol around host-native skills and hooks:

```text
User prompt
    |
    +-- UserPromptSubmit hook --> bounded ledger reminder
    |
    +-- using-littlepowers --> direct | compact shape | full shape
                                  |
                                  +--> executing-plans
                                           |
Coordinator-only state CLI <---------------+
    |
    +-- trusted local store: .littlepowers/state.json
    +-- revision check + cross-process lock + atomic replace
```

SessionStart uses the same reader to return a fuller snapshot. SubagentStart returns a smaller read-only ownership snapshot. Hooks never write state.

## State store

The worktree-local `.littlepowers` directory is retained because Codex commonly protects `.git` from writes. The store is hardened instead of moved into the Git directory.

Before use, the store:

1. resolves the workspace root;
2. rejects a symlink or reparse point at `.littlepowers` or `state.json`;
3. verifies the resolved state directory remains inside the root;
4. rejects a Git-tracked state file;
5. checks that `.littlepowers/state.json` is ignored when Git is available;
6. reads at most 64 KiB from a regular, single-link file with trusted ownership and permissions;
7. verifies serialized output remains within 64 KiB before atomic replacement.

Mutations acquire a cross-platform advisory lock for the complete read-check-write transaction. The caller supplies `workflow_id` and `expect_revision`; a mismatch raises a conflict and leaves the file unchanged. The writer then increments the revision and performs flush, file fsync, atomic replace, and a best-effort directory fsync.

On POSIX, the transaction opens the resolved workspace one non-link component at a time, then retains a descriptor for `.littlepowers` opened relative to that workspace. Lock creation, state reads and writes, temporary files, replacement, and archive creation use descriptor-relative operations, so swapping an intermediate workspace path or the lexical state directory cannot redirect a write.

Schema 1 is converted in memory with a deterministic UUID derived from workspace and existing state. The next valid mutation persists schema 2. This lets old ledgers recover without a read-side write from hooks.

## Artifact paths

Artifact values are data, not instructions. The validator accepts only normalized relative Markdown paths under the workspace. The state CLI reads an artifact only when its workflow ID and revision match the caller's snapshot, walks without following links where descriptor-relative operations are supported, limits content to 128 KiB, and returns snapshot identifiers plus an untrusted-data label. This removes the previous contradiction where the hook called data untrusted and then ordered the model to open it.

Artifact placement uses explicit declaration rather than directory inference. The latest user request wins; otherwise a current repository instruction must name a root for new workflow artifacts. Existing directories, backlinks, historical files, and tool-branded roots are ignored for selection. With no declaration, each phase uses its `docs/littlepowers/...` default. The selected exact paths are checkpointed in the ledger; a later migration must move the files first and then replace all affected artifact references with one revision-checked state CLI checkpoint.

## Prompt cadence and authority

The hook output contains `workflow_id`, revision, status, phase, objective, next action, timestamps, and bounded artifact/checkpoint data. It does not contain imperative workflow policy.

The router owns behavioral semantics:

- the latest user request wins;
- a ledger is a continuity hint and may be stale;
- related follow-ups update the plan;
- side questions return to a recent active workflow's recorded action, while paused or stale-by-age work stops unless explicitly continued;
- unrelated work preserves the workflow and moves to another task/worktree unless the user chooses replacement;
- no magic cancellation words are required when intent is otherwise clear.

This separates dynamic facts from static rules and avoids repeating policy in every phase skill.

## Planning depth

Planning depth follows decision risk, not model effort or file count:

| Route | Use when | Artifact |
| --- | --- | --- |
| Direct | Outcome and approach are already clear | None; optional execute ledger for long work |
| Compact | A few connected decisions need shaping but risk is moderate | One shape brief |
| Full | Explicit request, or material unresolved architecture, security, migration, cross-system, irreversible, or costly-rollback choices | Brainstorm, spec, design, plan |

Higher reasoning effort does not select a deeper route. Once a decision is settled, the skills tell the model to act without reopening it or adding unrequested abstractions.

## Multi-agent ownership

The root coordinator is the sole ledger writer. Workers receive task briefs and read-only workflow context, then return evidence. The coordinator can execute independent plan items in dependency-safe waves and checkpoint after integrating results. Separate top-level objectives require separate worktrees.

This is compatible with Codex Ultra and Claude dynamic workflows without making Littlepowers another orchestrator.

## Platform path strategy

Claude Code expands `${CLAUDE_PLUGIN_ROOT}` in skill content. Codex supplies the absolute loaded skill path and plugin hook root. The router defines one `<state-cli>` path for the session, and internal phase skills reuse it rather than independently guessing the plugin root. A management skill gives users a harness-native entry point so README commands do not assume the source repository is the current directory.

## Publication boundary

v0.3 prepares a prerelease and community files but does not change repository visibility. Model compatibility claims distinguish official design review, harness validation, and authenticated live-model evaluation.
