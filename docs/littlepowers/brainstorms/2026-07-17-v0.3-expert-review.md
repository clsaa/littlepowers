# Littlepowers v0.3 expert review brainstorm

**Date:** 2026-07-17

**Status:** Selected direction

## Outcome

Make Littlepowers a credible, model-neutral planning and recovery plugin for Codex and Claude Code. It must help an agent return to unfinished work without pretending that a plugin can control every model turn.

## Evidence considered

Five independent reviews covered architecture and security, OpenAI and Codex, Anthropic and Claude Code, daily AI-coding use, and open-source adoption. The review also compared Superpowers v6.1.1 and current official guidance for GPT-5.6 Sol, Claude Fable 5, and Claude Opus 4.8.

The reviews agreed on five problems:

1. A SessionStart hook cannot cover ordinary prompts or same-session steering.
2. Atomic file replacement does not prevent concurrent writers from losing updates.
3. The state store trusts symlinks, tracked files, oversized input, and artifact paths too much.
4. Four separate planning documents are excessive for medium-sized tasks with fixed decisions and can amplify overplanning at high reasoning effort.
5. Public adoption needs calibrated claims, a support matrix, security documentation, contribution paths, and stable release metadata.

## Options

### A. Add more mandatory instructions

Keep one state file and strengthen the wording that tells the model to continue.

This is small, but it does not fix prompt cadence, concurrent writes, or the trust boundary. It also conflicts with current model guidance to remove repeated scaffolding.

### B. Turn Littlepowers into a full orchestrator

Manage multiple objectives, subagents, branches, reviews, and task graphs inside the plugin.

This could be powerful, but it would duplicate Codex Ultra, Claude dynamic workflows, and much of Superpowers. It would also create the model conflicts the project is intended to avoid.

### C. Build a small recovery protocol with proportional shaping

Keep the host harness in charge of orchestration. Add a prompt-boundary reminder, a hardened revisioned ledger, and explicit coordinator ownership. Route work through direct, compact, or full shaping based on decisions and risk rather than file count.

This addresses the observed failures while preserving the project's small scope.

## Selected direction

Choose option C.

- SessionStart injects a bounded factual snapshot.
- UserPromptSubmit injects a shorter factual reminder on every supported prompt boundary.
- The latest user request remains authoritative; the ledger is continuity data, not a higher-priority instruction.
- One worktree keeps one active workflow. Parallel top-level objectives use separate worktrees.
- A workflow has an ID and monotonic revision. Stale writers fail instead of overwriting newer state.
- In multi-agent runs, the coordinator is the only ledger writer. Workers receive read-only context.
- Direct tasks may be tracked without planning artifacts when they are long-running.
- Medium work may combine brainstorm, spec, design, and plan into one shape brief.
- Full four-artifact shaping is reserved for explicit requests, architecture, security, migrations, cross-system work, or costly rollback.

## Brand and publication

Keep `littlepowers` for v0.3 so this review does not silently rename an existing repository and plugin. Before making the repository public, decide whether to adopt `planthread`, the expert panel's preferred independent long-term name. Do not change repository visibility without explicit owner approval.
