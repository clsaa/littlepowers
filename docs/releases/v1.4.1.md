# Littlepowers 1.4.1 — Native checklist visibility

Fix native task visibility across planning and meaningful multi-step Direct
work while keeping tiny tasks lightweight. The shared adapter uses the tools
actually exposed by Codex, Claude Code, Qoder, or OpenCode, with stable scoped
IDs, no-op detection, recovery reconciliation, and manual-edit conflict safety.
It never creates sidebar conversations or subagents to simulate a checklist.

Codex 0.152.0 defaults `update_plan` to off. Opt in by setting
`tools.update_plan.enabled = true` at the root of Codex `config.toml`, then
start a new task/session (restart the desktop host if it retains old settings).
Littlepowers documents this switch but does not change global configuration
without authorization. Model and reasoning-effort settings remain untouched.

## Acceptance evidence

Two real Codex 0.155.1 Sol/max probes produced native checklist create/update/
completion events: one with a temporary override, one using the saved opt-in.
After enabling it, the user explicitly confirmed on 2026-09-20 that the plan
checklist was visible in the desktop interface and authorized this release.
This is user-reported visual acceptance, not an assistant-captured screenshot.

See [the opt-in follow-up](../littlepowers/evidence/2026-09-20-codex-plan-opt-in.md)
and [implementation checks](../littlepowers/evidence/2026-09-20-native-task-mirror.md).
The final release gate runs the aggregate unit suite, all 11 skill validators,
host package checks, exact-commit cross-platform CI, and exact-tag install smoke.

## Limits and upgrade

Native tools and rendering remain host-dependent. Claude Code's bounded live
smoke timed out; Claude/Qoder/OpenCode positive UI certification is not claimed.
Their adapters are capability-conditional. Receipts do not override scope,
approval, or Outcome Lock; conflicting native edits require reconciliation.

Protocol 1.3 and schema 4 are unchanged. No background scans, telemetry,
runtime dependencies, model calls, or automatic subagents were added. Install
from `v1.4.1` and start a new task/session to load the updated skills.
