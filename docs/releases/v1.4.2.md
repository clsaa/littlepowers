# Littlepowers 1.4.2 — Verification integrity

Verification recording and completion now revalidate the exact approved plan
path, complete bytes (including prose outside the Plan Map), consumed approval
and current embedded sources. Failed completion writes leave status and
revision unchanged.

Before running checks, capture explicitly declared candidate inputs with
`verification-inputs --file <path>`; repeat `--file` for relevant files and use
`--absent <path>` for intended deletions. Copy the snapshot unchanged into the
Verification Record's `inputs` after running the checks. Recording and
completion both reject changed files or reappearing deleted files. A genuinely
manual outcome without project-file inputs requires `--manual-reason`.

## Upgrade

Install from the exact `v1.4.2` tag and start a new task/session. Protocol 1.3
and schema 4 are unchanged. Existing receipts remain readable, but completing
work requires capturing inputs, rerunning checks and recording fresh evidence.
Do not add current hashes to old test results or mix runtime versions within
an active workflow. See [scope and migration](../../references/outcome-lock.md#verification-input-freshness-142).

## Scope and evidence

The change adds 24 regression tests to the 222-test baseline, including
approval/source drift, atomic failures, explicit absence, legacy records,
manual outcomes and unsafe paths. Release validation runs the full suite,
all 11 skill validators, Codex and Claude package validators, compilation and
host syntax checks. Cross-platform results must be read from the release
commit's GitHub Actions run; local Linux checks do not certify other systems.

Hashes cover only declared bytes and absence. They do not prove tests ran,
cover undeclared files or environment state, or prevent later modifications.
Unsupported inputs, including hidden paths, require an explicit scope limit.
No automatic scans, telemetry, runtime dependencies or automatic subagents
were added. Hosted skill-driven use does not imply automatic Hook execution.
